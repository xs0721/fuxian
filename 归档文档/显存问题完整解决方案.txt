一、显存使用分析
================================================================================

【实测数据】

OPT-125M (单个模型):
• 模型大小: 245MB
• 生成时峰值: 257MB
• 总显存: 8188MB (8GB)
• 剩余: 7931MB

【问题出在哪？】

如果你运行run_experiment.py报显存不足，可能是：

问题1：多个算法同时运行？
• 每个算法可能加载自己的模型副本
• 18个算法 × 257MB = 4.6GB（应该还够）

问题2：批处理太大？
• 如果batch_size太大，会占用更多显存
• 检查代码中的batch_size设置

问题3：梯度累积？
• 如果没有torch.no_grad()，会存储梯度
• 梯度会占用额外显存

问题4：内存碎片？
• 长时间运行，显存碎片化
• 需要定期清理

问题5：测试代码有问题？
• 某些测试可能有显存泄漏

三、如果要复现AWT或RL-Watermark
════════════════════════════════════════════════════════════════════════════════

【关键问题】8GB显存够不够？

【AWT】(Adversarial Watermarking Transformer)

模型: LSTM Seq2Seq + GAN
• 生成器: LSTM编码-解码器（约100-200MB）
• 判别器: LSTM分类器（约50-100MB）
• 训练batch: 80个样本
• 预估显存: 4-6GB

结论: 8GB勉强够，但需要：
• 使用小batch_size（40-60）
• 使用梯度累积
• fp16混合精度训练

【RL-Watermark】

模型: GPT-2 + PPO
• 主模型: GPT-2 small（约500MB）
• 参考模型: GPT-2 small副本（约500MB）
• Value网络: 额外网络（约100MB）
• 训练显存: 2-4GB（取决于配置）

结论: 8GB够，但需要优化：
• 使用gradient checkpointing
• 小batch_size
• fp16训练

【显存优化技巧】

1. 梯度检查点（Gradient Checkpointing）
```python
model.gradient_checkpointing_enable()
```
显存减少50%，速度慢30%

2. 混合精度训练（fp16）
```python
from torch.cuda.amp import autocast, GradScaler
scaler = GradScaler()

with autocast():
    loss = model(...)
```
显存减少40-50%

3. 梯度累积（小batch模拟大batch）
```python
accumulation_steps = 4
for i, batch in enumerate(dataloader):
    loss = model(batch) / accumulation_steps
    loss.backward()

    if (i + 1) % accumulation_steps == 0:
        optimizer.step()
        optimizer.zero_grad()
```

4. 使用更小的模型
• AWT: 原论文用AWD-LSTM，可以用更小的
• RL: 用GPT-2 small而不是medium
