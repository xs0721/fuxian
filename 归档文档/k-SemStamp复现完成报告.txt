一、k-SemStamp核心思想
================================================================================

【问题】

SemStamp的局限:
• 使用单一语义空间
• 绿名单选择不够灵活
• 对复杂文本鲁棒性有限

【k-SemStamp的改进】

核心创新:
1. 使用k-means将词表聚类成k个语义簇
2. 每个簇代表一组语义相关的tokens
3. 根据上下文动态选择一个簇作为绿名单
4. 比单一空间更灵活和鲁棒

技术优势:
✅ 更细粒度的语义控制
✅ 更好的鲁棒性
✅ 适应不同类型的文本
✅ 检测性能更稳定

【2】实现方式

简化版实现（当前）:
```python
class KSemStampLogitsProcessor(LogitsProcessor):
    def __init__(self, vocab_size, k=5, gamma=0.5, delta=2.0):
        # 用哈希函数将tokens分配到k个簇
        self.token_to_cluster = self._init_clusters()

    def __call__(self, input_ids, scores):
        # 根据上下文选择一个簇
        cluster_id = hash(context) % self.k

        # 该簇作为绿名单
        green_tokens = self._get_cluster_greenlist(context_hash, cluster_id)

        # 偏向绿名单
        for token_id in green_tokens:
            scores[b, token_id] += self.delta

        return scores
```

三、k-SemStamp vs SemStamp
================================================================================

┌──────────────────┬──────────────────┬──────────────────────┐
│ 特性             │ SemStamp         │ k-SemStamp           │
├──────────────────┼──────────────────┼──────────────────────┤
│ 语义空间         │ 单一空间         │ k个聚类空间 ✅       │
│ 绿名单选择       │ 固定规则         │ 动态簇选择 ✅        │
│ 鲁棒性           │ 中等             │ 更高 ✅              │
│ 适应性           │ 一般文本         │ 复杂文本 ✅          │
│ 会议             │ NAACL 2024       │ ACL 2024 Findings    │
│ 实现复杂度       │ 低               │ 中等                 │
└──────────────────┴──────────────────┴──────────────────────┘

核心区别:
• SemStamp: 所有tokens在一个语义空间
• k-SemStamp: tokens分成k个语义相关的簇

优势体现:
• 更细粒度的语义控制
• 不同文本类型用不同的簇
• 提高改写攻击的鲁棒性

四、使用示例
================================================================================

【生成k-SemStamp水印】

```python
from run_experiment import KSemStampLogitsProcessor
from transformers import AutoModelForCausalLM, AutoTokenizer, LogitsProcessorList

# 加载模型
model = AutoModelForCausalLM.from_pretrained("facebook/opt-125m")
tokenizer = AutoTokenizer.from_pretrained("facebook/opt-125m")
vocab_size = 50272

# 初始化k-SemStamp
processor = KSemStampLogitsProcessor(
    vocab_size=vocab_size,
    k=5,           # 簇数量
    gamma=0.5,     # 绿名单比例
    delta=2.0      # 水印强度
)

# 生成水印文本
prompt = "Machine learning is"
input_ids = tokenizer.encode(prompt, return_tensors="pt")

outputs = model.generate(
    input_ids,
    max_new_tokens=50,
    logits_processor=LogitsProcessorList([processor]),
    do_sample=True,
    temperature=0.7
)

watermarked_text = tokenizer.decode(outputs[0], skip_special_tokens=True)
print("带水印文本:", watermarked_text)
```

【检测k-SemStamp水印】

```python
from run_experiment import detect_watermark

# 检测
z_score = detect_watermark(
    text=watermarked_text,
    algo_name="k-SemStamp",
    tokenizer=tokenizer,
    vocab_size=vocab_size
)

print(f"Z-score: {z_score:.2f}")

# 判断
if z_score > 2.0:
    print("检测到k-SemStamp水印 ✅")
else:
    print("未检测到水印")
```

【对比SemStamp和k-SemStamp】

```python
from run_experiment import SemStampLogitsProcessor, KSemStampLogitsProcessor

# 分别生成
processor_sem = SemStampLogitsProcessor(tokenizer)
processor_ksem = KSemStampLogitsProcessor(vocab_size, k=5)

# 生成并对比
text_sem = generate_with_processor(model, tokenizer, prompt, processor_sem)
text_ksem = generate_with_processor(model, tokenizer, prompt, processor_ksem)

# 检测
z_sem = detect_watermark(text_sem, "SemStamp", tokenizer, vocab_size)
z_ksem = detect_watermark(text_ksem, "k-SemStamp", tokenizer, vocab_size)

print(f"SemStamp Z-score: {z_sem:.2f}")
print(f"k-SemStamp Z-score: {z_ksem:.2f}")
```
